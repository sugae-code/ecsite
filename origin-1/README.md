# ORIGIN-1 — 無から「原権」を発行する社会プロトコル

**現状：技術的な原型。参加者0人、入金0円、法的に確立した収益権0件。**

## 発想

商品・サービスを売らず、既存資産も売らずに、社会の合意によって**新しい種類の受益地位（原権）**を生み出す。

原権 `ORIGIN-1/GENESIS/1` を1単位発行し、初期保有者 `ORIGINATOR` を置く。これは概念上の地位であって、通貨・証券・銀行残高・第三者への確定債権ではない。

このルールを**明示的に選んだ人が、もともと他者に贈ろうとしていた金額の一部**を原権保有者へ割り当てる。送金者には何の対価も約束しない。サービス利用料でも投資でも紹介報酬でもない。参加しない人には何の負担もない。

**GIFT-1との相違**：創始者本人への直接寄付を募集するのではなく、AからBへの贈与を行うときにAが自ら選ぶ「第三者への分配規則」を設ける。創始者自身は毎回の支払いに関与しない。ただし採用理由と拡散経路は未解決であり、導入を選ぶ合理的・文化的動機の検証が必要。

## 金額の流れ（仮の例）

AはBへ毎月1000円を贈ろうとしている。Aが「うち10%を原権保有者に配分する」と明示的に選んだ場合にのみ、
- Bへ900円
- 原権の保有者へ100円
- Aの負担は合計1000円（追加請求なし）

実際はA自身が銀行など正規の経路を使ってそれぞれに送金設定する。**このコードに送金機能、口座情報、金銭の預かり、請求機能はない。** Aは将来の定期振込設定を自分の銀行で止められる。

## 年1000万円という目標を検査する

上記の1000円/月・10%配分なら、原権へ100円/人/月。
`10,000,000 ÷ (100×12) = 8,333.33...` なので、**8,334人**が一年を通して任意の贈与を実行する必要がある。手数料・税引前で10,000,800円/年相当になる算術例。参加者や受領額が実際に存在するという意味ではない。

## 安全条件と法的境界

- 知識不足への付け込み、強制、虚偽の実績、本人に隠した料金、既定チェック、同意なき課金を禁止。
- 参加者は自分の財産を、自分で指定する相手と割合にのみ配分する。誰も会員勧誘の報酬や利益を受け取らない。
- 受益地位を作るだけでは、非参加者の財産への請求権は生まれない。
- 個別に実際の贈与を成立させるには当事者の意思が必要。民法549条以下（書面によらない贈与の取扱いは550条等）を確認する必要がある。
- 受取額は税務上の取扱いを個別検討する。国税庁は個人の暦年課税による贈与の基礎控除110万円を「受贈者1人につき1年間の総額」と説明している。三者配分や原権の扱いが常に贈与に該当するとは断定しない。
- 法律・実務上の契約、金融規制、税、送金可能性は未検証。受益権の譲渡や配当、トークン販売、投資募集はこの原型に含めない。
- 銀行口座・住所・本人情報はこのリポジトリに記載しない。

## 実装

- `origin-right.mjs` : 初期原権の発行状態、明示同意のある贈与案の計算、目標人数の逆算
- `origin-right.test.mjs` : 同意・金額配分・現金との区別を検査
- `node --test origin-1/origin-right.test.mjs` で検査

## 最大の未解決課題

**原権を発行したことと、他人がその原権に対して現金を支払うことは別。** このルールを選びたくなる参加者の動機と広がりが実証されなければ、年1000万円の収益資産にはならない。
